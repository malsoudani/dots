# Using Doctrine with coding agents

Doctrine reaches an agent through the instruction file that agent already reads. The `doctrine` command writes that file, records what it wrote, and removes it again without touching anything else. This guide has three parts: the recipe that works for every agent, one generated section per supported agent, and what to do when your agent or model is not listed.

## The recipe

1. List the agents Doctrine knows, then the ones present on this machine and in this project:

   ```sh
   doctrine agents
   doctrine detect --path .
   ```

2. Preview. `--dry-run` prints every planned action and a diff, and writes nothing:

   ```sh
   doctrine install --agent detected --dry-run
   ```

3. Install, then confirm with the agent's own verify step (listed in its section below):

   ```sh
   doctrine install --agent detected
   doctrine status
   ```

`--agent` takes one id, several ids separated by commas, `all`, or `detected`.

## Scopes

Pick the narrowest scope that covers the work.

| Scope | Flag | Applies to | Written under |
|---|---|---|---|
| project | `--scope project` (default) | one repository | the repository root: `--path`, else the git top level of the current directory |
| workspace | `--scope workspace --path DIR` | every project inside one directory | `DIR`, for agents that read instruction files from parent directories |
| global | `--scope global` | every project of this user | the agent's user-level location |

`namespace` is an alias of `workspace`. `user` is an alias of `global`. When an agent has no workspace support, add `--each-repo` to install into every git repository found under `DIR`; `--depth` limits the search (default 2).

## What gets written

- The agent's instruction target. This is either a file Doctrine owns outright, or a marked block inside a file you share with it, from `doctrine:begin` to `doctrine:end`. Everything outside the block is preserved byte for byte.
- A reference directory: `.doctrine/` in the project or workspace, `~/.doctrine/` for the global scope. It holds the full rule text, the how-to guides, the checklists and `rules.json`. The installed text lists rule titles and points here for depth. Skip it with `--no-reference`. Add the reference implementations with `--with-examples`.
- A manifest entry, so that `status`, `update` and `uninstall` know what exists.

Commit these files to share Doctrine with the team. To keep them out of version control instead, pass `--local`: the installer lists them in the repository's local exclude file, so nothing shows up as untracked.

## Tiers and profiles

`--tier` sets how much text the agent loads on every request:

- `micro`: the operating instructions and the titles of the most important rules.
- `compact`: every principle and rule title, plus pointers into the reference directory. This is the default.
- `full`: every rule in full, the checklists and the how-to guides.

`--profile backend` or `--profile frontend` drops the other side's rules. When an agent documents a size limit, the installer falls back to the next smaller tier and says so.

### Claude Code (`claude`)

Anthropic. Kind: agent. Confidence: high.

**Reads.**

- Project: `.claude/rules/doctrine.md` (file)
- Global: `~/.claude/rules/doctrine.md` (file)
- Workspace: `CLAUDE.md` (block)
- Reads `AGENTS.md` natively.
- Also reads: `CLAUDE.local.md`, `AGENTS.md`.
- Sources: [1](https://docs.claude.com/en/docs/claude-code/memory), [2](https://docs.claude.com/en/docs/claude-code/memory).

**Install.**

```sh
doctrine install --agent claude
doctrine install --agent claude --scope global
doctrine install --agent claude --scope workspace --path DIR
```

**Verify.** Run `/doctor prompt-audit` and look for the installed file in the audited list.

**One-shot.** `claude -p "review this change"`

**Notes.**

- Project and user memory load at session start; start a new session after installing.
- `.claude/rules/` scopes rules to file types; `~/.claude/rules/` is the user-scope equivalent.
- AGENTS.md is read in place of CLAUDE.md when no CLAUDE.md exists.

- Global: `~/.codex/AGENTS.md` (block)

## Custom files

Any file that an agent or tool reads as instructions can carry Doctrine: a sub-agent prompt, a system prompt file, a prompt template.

```sh
doctrine install --agent custom --file prompts/reviewer.md
doctrine install --agent custom --file prompts/system.txt --comment hash
```

This inserts the same marked block. Use `--comment hash` when the file is not Markdown or HTML and needs `#` comment markers. Uninstall with the same `--agent custom --file PATH`.

## Raw models and runtimes

A model with no agent around it takes Doctrine as its system prompt.

- Print the text and pass it yourself: `doctrine print --tier compact > doctrine.md`. Supply that file as the system prompt of your API call or chat template.
- Small context window: use `--tier micro`. It fits in 4,000 characters. `compact` fits in 12,000.
- A local model runtime listed above installs in one of two ways: as a model definition built on a base model that you name with `--base MODEL`, or as a plain prompt file plus the command that loads it.
- `--reference-dir PATH` changes where the Deep dives section points. A model can follow those pointers only if it can read files. When it cannot, use `--tier full` if the context window allows.

## Update and uninstall

```sh
doctrine status                  # ok, outdated, modified or missing, for each install
doctrine update                  # re-apply every recorded install with its recorded options
doctrine uninstall --agent ID    # pass the same --scope and --path as the install
```

Run `update` after you pull a new version of Doctrine. `uninstall` removes the block or file, the reference directory once no other install uses it, and any directory it created that is now empty. A file that existed before the install returns to its exact previous bytes.

## Troubleshooting

- **The agent ignores the rules.** Run the agent's verify step. Most agents read instruction files only when a session starts, so restart the session.
- **The installer refuses to overwrite a file.** The target exists and Doctrine did not write it. Move your content elsewhere, or pass `--force` to back the file up beside itself and replace it.
- **The installer says `use --each-repo`.** The agent does not read instruction files from parent directories. Install into each repository instead.
- **The text was cut down to a smaller tier.** The agent documents a size limit. Every rule is still in the reference directory.
- **Status says `modified`.** Someone edited inside the marked block. Move the edit outside the block, then run `doctrine update`.
- **Two agents share one file.** This is expected. One block serves both, and it is removed when the last of them is uninstalled.
- **Nothing was detected.** `detect` looks for each agent's command on `PATH` and for its configuration directory. Name the agent explicitly with `--agent ID`.
